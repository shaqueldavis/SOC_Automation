I know what your thinking. Is this safe 👀?

short answer:

Yes.

Wazuh normally uses a certificate that your browser does not automatically trust. Its documentation confirms that a certificate warning is expected when first accessing the dashboard. This does not mean the connection is unencrypted—it means the browser cannot independently verify the server’s identity. <br>
<a href="https://documentation.wazuh.com/current/installation-guide/wazuh-dashboard/step-by-step.html?utm_source=chatgpt.com">Wazuh dashboard installation documentation</a>

Why the warning appears

There are two separate HTTPS protections:

Encryption: Prevents others from easily reading your Wazuh username, password, and dashboard traffic.
Identity verification: Confirms that the server is genuinely your Wazuh instance.

Your Wazuh connection is probably encrypted, but the browser does not trust the certificate authority that issued the certificate. This is common with self-signed or privately issued certificates.

Click "Advanced" on the web browser warning page and "Continue to WAZUH_SERVER_IP (unsafe)" <br>
**Note: WAZUH_SERVER_IP should be the IP address of your Wazuh cloud instance.***

### Update Host Name (Optional) 

Earlier you may remember that I incorrectly named my Wazuh cloud instance "SOC-Lab" instead of "SOC-Lab-Wazuh". Because of that my ssh session prompt has been reading as "SOC-Lab" even though I updated the label after successfully creating the instance. However, changing the label after the instance is created does not change the host name. This has to be done inside of the ssh session. <br>
Here I will provide you with instructions on how to make this change.

While the ssh session is running, to change the host name, enter the command: 
```
sudo hostnamectl set-hostname SOC-Lab-Wazuh
```

Then confirm the change by running:
```
hostnamectl
```

<br>

<img width="1240" height="432" alt="Screenshot 2026-08-04 102600" src="https://github.com/user-attachments/assets/8947b97b-f442-4025-a8e4-6a274f1fb94f" />

<br>
<br>
<br>
<br>

Now check the host file:
```
sudo nano /etc/hosts
```

Update the host name on the line containing it. In my case the old name is listed twice. I will delete both and replace it with the updated name once. **Do not delete the IP address that proceeds it***.
<br>

Yit `ctrl` + `x` to exit

You will be prompted to save the file. Hit `y` and enter to save, then hit enter again to keep the same name.
