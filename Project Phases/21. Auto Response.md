# Automated Response

1. Create the response script

On your Windows 11 VM, open PowerShell as Administrator and navigate to:

```powershell
cd "C:\Program Files (x86)\ossec-agent\active-response\bin"
```

<img width="1787" height="193" alt="image" src="https://github.com/user-attachments/assets/c83d83db-936d-4c20-b5af-b4e39cb3c7dd" />



Create the script:
```powershell
notepad contain-mimikatz.cmd
```

Select "Yes" to create a new file.

<img width="1306" height="471" alt="image" src="https://github.com/user-attachments/assets/af23c4a3-4b0a-4580-9184-935989040b98" />


Place this inside it:

``` batch
@echo off
setlocal

REM Read the Wazuh Active Response event from standard input
set /p WAZUH_EVENT=

REM Define the Active Response log
set "LOG_FILE=C:\Program Files (x86)\ossec-agent\active-response\active-responses.log"

REM Attempt to terminate Mimikatz
taskkill /F /IM mimikatz.exe >nul 2>&1

if %ERRORLEVEL% EQU 0 (
    echo %DATE% %TIME% wazuh-active-response: Mimikatz process terminated successfully.>>"%LOG_FILE%"
) else (
    echo %DATE% %TIME% wazuh-active-response: Mimikatz process was not running when containment executed.>>"%LOG_FILE%"
)

endlocal
exit /b 0
```

<img width="1828" height="986" alt="image" src="https://github.com/user-attachments/assets/33bf46ec-1890-4bb1-95db-dbaf1cb47510" />

The second result is not necessarily a failure. Mimikatz may have already closed between detection and response.

Close and save the file.

2. Configure the Wazuh command

Connect to your Wazuh server via ssh and open the ossec.conf file.

```bash
sudo nano /var/ossec/etc/ossec.conf
```

Scroll down and create some space between `</global>` and `<integration>`. Copy and paste in the code:
```xml
  <command>
    <name>contain-mimikatz</name>
    <executable>contain-mimikatz.cmd</executable>
    <timeout_allowed>no</timeout_allowed>
  </command>
```
This defines the script Wazuh is allowed to execute.

3. Connect it to rule 100002

Create a little more space between `</command>` and `<integration>` then add this separate block:

```xml
  <active-response>
    <command>contain-mimikatz</command>
    <location>local</location>
    <rules_id>100002</rules_id>
  </active-response>
```

The settings mean:

| Setting    | Purpose                                       |
| ---------- | --------------------------------------------- |
| `command`  | Selects your containment script               |
| `location` | Runs it on the agent that generated the alert |
| `rules_id` | Triggers it only for your Mimikatz rule       |


<img width="2473" height="876" alt="image" src="https://github.com/user-attachments/assets/bb5c2bc5-17a0-4d79-8e6d-87974c206ef0" />

Hit `ctrl` + `x`, `y`, and `enter` to save.

4. Validate and restart Wazuh

Before restarting, validate the configuration:

```bash
sudo /var/ossec/bin/wazuh-analysisd -t
```
This command tests the Wazuh analysis configuration for errors without starting or restarting the Wazuh manager.

Check the exit code immediately after.
```bash
echo $?
```
An exit code of 0 generally means the configuration test succeeded. Any nonzero value indicates a problem that needs investigation.

<img width="1183" height="131" alt="image" src="https://github.com/user-attachments/assets/77dd75ce-1f6b-48a9-a3cf-e07e01a76f75" />

If validation succeeds, restart Wazuh. This may take a while.
```bash
systemctl restart wazuh-manager
```


Confirm that it restarted successfully:
```bash
systemctl status wazuh-manager --no-pager
```

5. Test the containment

Inside the isolated Windows VM:

start Mimikatz by navigating to its folder `Downloads` > `mimikatz_trunk`. `Shift` + `right click` in the folder and select "Open PowerShell window here". <br>

Execute mimikatz.
```bash
.\mimikatz.exe
```

- Start Mimikatz.
- Allow Sysmon to record its process creation.
- Confirm Wazuh rule 100002 fires.
- Observe whether the Mimikatz process closes automatically.
- Examine this file on Windows:
  - `C:\Program Files (x86)\ossec-agent\active-response\active-responses.log`
